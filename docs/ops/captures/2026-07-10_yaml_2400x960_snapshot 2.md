## A/V pipeline
- **Video:** H.264, forward-ENCRYPTED (box holds no plaintext), host decrypt `ok=190 fail=0`. Screen is
  delta-driven — `ok` climbs on UI change, plateaus on a static screen.
- **Audio:** media stream 100, PCM 48000 Hz / 16-bit / **stereo big-endian** (host byte-swaps, docs/carplay/02_SESSION_LIFECYCLE.md),
  decrypt `fail=0`.
- **Drops:** ocbmd logged **zero** live-A/V backpressure/drops this session (contrast the stateful desync
  in docs/carplay/04_CAPABILITIES_AND_CONFIG.md that only reproduced without a clean reboot).

## Takeaways
- 2400×960 streams cleanly from a clean boot with headroom (~27% CPU). The forward-encrypt path is fine at
  this resolution as long as no frame is dropped — the drop→counter-desync fragility (task #33) is the
  real long-term risk, not raw CPU.
- The turnkey chain (boot → SUBSCRIBE → projection → ARM → RECORD → fwd-enc) is fully automatic and
  now config-driven end-to-end.
